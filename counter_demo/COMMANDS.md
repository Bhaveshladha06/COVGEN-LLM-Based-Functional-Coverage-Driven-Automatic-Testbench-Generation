# Counter demo — run each step yourself and look at what appears

Nothing here is generated by the LLM. Five hand-written files, so the result is
the same every time and you can check it against what this page says.

**The stimulus deliberately stops at count = 5.** So these bins CANNOT be hit:

| Bin | Why it cannot be hit |
|---|---|
| `count_cp.high` (8..14) | counter never gets past 5 |
| `count_cp.max` (15) | same |
| `wrap_cp.wrap` (15 => 0) | never reaches 15, so never wraps |
| `count_x_en` pairs with `high` or `max` (4 of the 8) | same |

Everything else should be hit. **That list is the answer key.** Worked out by
hand from the stimulus:

| coverpoint | bins hit / total | score |
|---|---|---|
| `count_cp` | 2 / 4 — `zero`, `low` | 50% |
| `en_cp` | 2 / 2 | 100% |
| `rst_cp` | 2 / 2 | 100% |
| `wrap_cp` | 0 / 1 | 0% |
| `count_x_en` | 4 / 8 | 50% |
| **covergroup** = average of the five | **10 / 17 bins** | **60%** |

---

## Run it

Six scripts, one command each. **Do not paste the long irun command by hand** —
copying multi-line commands out of a chat window drags in invisible characters
(non-breaking spaces), and irun then reports things like

    *E,FMUK: The type of the file ( -coverage) could not be determined

which looks like a tool failure but is just a mangled paste.

    source "$HOME/miniforge3/etc/profile.d/conda.sh"
    conda activate assergent
    source ~/.bashrc
    cd ~/Desktop/BTP/Coverage_TB/counter_demo

    bash 1_simulate.sh            # run the simulation, write the database
    bash 2_show_database.sh       # what irun actually created on disk
    bash 3_make_reports.sh        # IMC turns the database into two reports
    bash 4_show_bins.sh           # exactly which bins are empty
    bash 5_gui.sh                 # the same thing clickable (needs ssh -X)
    bash 6_prove_per_instance.sh  # delete the magic line, watch it break

Each script prints what to expect and what to run next.

---

## What each step shows

**1_simulate.sh** — the irun command with every flag explained:

| Flag | Meaning |
|---|---|
| `-sv` | treat the files as SystemVerilog |
| `-coverage all` | turn coverage collection on |
| `-covoverwrite` | overwrite the old database instead of erroring |
| `-covscope scope` | name the folder inside the database |
| `-covtest test` | name the run inside that folder |
| `-covdut counter` | score only these modules, not the testbench |
| `-top top_counter` | which module is the top level |

Then prints the simulator's own score — no database involved.

**2_show_database.sh** — what irun wrote:

    cov_work/scope/*.ucm         the MODEL -- what bins exist
    cov_work/scope/test/*.ucd    the DATA  -- which bins were hit

Two separate files. IMC needs both.

**3_make_reports.sh** — runs IMC with `load -run scope/test`, which opens
`cov_work/scope/test`. IMC only reads; it never runs your design. Produces
`summary.rpt` and `detail.rpt`.

In the summary, the `counter` row showing Functional `n/a` is **correct** — the
design itself contains no covergroups. The `counter_coverage` row is the one to
look at, and it should say 60.00%.

**4_show_bins.sh** — the uncovered-bin list, which is what the pipeline sends
back to the LLM.

**5_gui.sh** — the same bins in the IMC GUI, with hit counts per bin. Better for
screenshots; the text report is what the pipeline parses.

**6_prove_per_instance.sh** — removes `option.per_instance = 1;` and re-runs
everything else unchanged. IMC's Functional column returns to `n/a` while the
simulator still reports 60%. That single line is the difference between a
coverage database that records covergroups and one that does not.
